# Roadmap

This roadmap tracks future product and domain work for the React component library. Engineering tasks remain in GitHub issues.

Legend: [x] done, [~] in progress, [ ] not started

- [ ] **R1 - Make reference attribution consistently discoverable** - Review attribution placement at supported viewport sizes and ensure warnings, controls and chart height do not make required source information appear absent.
- [ ] **R2 - Add reference-attribution conformance tests** - Cover every supported growth reference in centile and SDS charts, including exact text, links and responsive visibility.
- [ ] **R4 - Complete the Node 24 migration** - Resolve and close GitHub issue #227 after validating build, test, Storybook and publication workflows.
- [ ] **R9 - Automate releases with `s/version++`** - Bring release practice into line with `rcpchgrowth-python` and `digital-growth-charts-react-client`: a script that validates a clean `live`, runs the full test/build/audit gate, bumps `package.json` (patch/minor/major), opens a `release/vX.Y.Z` PR, and leaves tagging/GitHub Release/npm publish to the existing merge-triggered `publish.yml`. Currently this repo bumps `package.json` and creates the GitHub Release by hand.
- [ ] **R10 - Migrate `@babel/preset-react` to 8.x** - Blocked on a coordinated Babel 7→8 upgrade: `@babel/preset-env` and `@babel/preset-typescript` are still on 7.x and pull in `@babel/core@7.x` transitively, conflicting with `preset-react@8.0.1`'s `@babel/core@^8.0.0` peer requirement. Dependabot PR #265 is parked pending this.
- [x] **R11 - Remove Fenton preterm reference scaffolding** - The University of Alberta declined to permit open-source distribution of the Fenton preterm growth reference, so the empty placeholder scaffolding for it (a `fenton` key with `data: null`/`[]` throughout the CDC chart-data files, `CentilesObject.ts`, `getDomainsAndData.ts`, `getFilteredMidParentalHeightData.ts`, and a related rendering hack in `CentileChart.tsx`) has been removed entirely rather than left in place. The CDC reference now has two segments (`cdc_infant`, `cdc_child`) instead of three. Added CDC-reference test coverage, which did not previously exist. Fenton support can be reintroduced later if a licence is agreed; see the removed code in this repository's history for the previous scaffolding shape.
- [~] **R12 - Deterministic `src/chartdata/` generation script** - `src/chartdata/*.ts` are hand-formatted TypeScript wrapping what is structurally `rcpchgrowth.chart_functions.create_chart()`'s return value; `agent-instructions.md` previously (and incorrectly) called this "hand-curated". A 2026-09-12 audit (`digital-growth-charts-server/.private/chart-coordinate-audit/`) found 39 of 45 compared modules had drifted from a fresh generation by up to ~1.2cm at some points, and issue #224 documents one confirmed defect (a malformed duplicate age point). `s/generate-chart-data` mirrors the server's `chart_data_cache.py` generation spec (same reference/sex/measurement-method matrix, same Turner exclusions) against a pinned `rcpchgrowth` version, for local, on-demand use whenever the upstream package changes. Emits data as plain `.json` (the toolchain already supports JSON imports via `@rollup/plugin-json`; `.ts` added TypeScript-compile cost and hand-formatting risk for zero benefit) with a thin, also-generated `.ts` wrapper per file so no consumer import site changes. CDC height and weight (4 files) are proven byte-for-byte identical against the committed data and are in `MANIFEST`. CDC BMI and OFC were investigated and deliberately excluded: BMI's centile _set_ is now correctly reproduced but a fresh generation returns `data: []` where committed data has `data: null` for `cdc_infant` (real `rcpchgrowth` error-handling drift, not a parameter mistake); OFC's centile set is correct but its generated age-grid points differ from committed data for an unidentified reason. See `chart-data-generation/generate.py` and `chart-data-generation/README.md` for the detail. Every other reference (uk-who, who, trisomy-21, trisomy-21-aap, turner) is entirely unmapped.
- [ ] **R13 - Extend `s/generate-chart-data` to the rest of the catalogue** - Depends on R12. For each remaining reference/measurement/sex combination: identify its actual historical centile-format parameters by diffing against the committed file (do not assume a named format matches from the filename - CDC height/weight, BMI and OFC all turned out to use different, non-obvious formats), resolve the CDC BMI/OFC discrepancies above, review each diff (magnitude, affected ages, whether it matches a known fix), visually verify in Storybook per `agent-instructions.md`'s Visual Verification section, then add to `MANIFEST` and replace the committed files. Closes #224.
- [ ] **R14 - Run `s/generate-chart-data` in CI** - Depends on R12/R13 covering the full catalogue. Regenerate `src/chartdata/` as a CI build step against the pinned `rcpchgrowth` version so the committed files can never silently drift from the calculation engine that produces them. Open decision: fail CI on an unexpected diff (drift caught immediately) vs. auto-open a PR with the regenerated files (drift reviewed on its own schedule) - recommend fail-closed, since this is clinical data and a silent auto-merge is the wrong default.
